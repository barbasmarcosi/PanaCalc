# PanaCalc V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy the complete PanaCalc V1 mobile-first dough calculator as an installable offline-capable PWA on GitHub Pages.

**Architecture:** A React + TypeScript + Vite SPA keeps dough mathematics in pure domain functions, browser persistence behind a storage adapter, and UI state in focused React components/hooks. Presets store formulas only, session state stores the current calculator state, and GitHub Actions verifies and deploys the static build.

**Tech Stack:** React, TypeScript, Vite, Vitest, Testing Library, CSS Modules/plain CSS, vite-plugin-pwa, ESLint, GitHub Actions, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-10-05-panacalc-v1-design.md`

## Global Constraints

- Mobile-first from approximately 320 px wide upward.
- Flour is the fixed 100% reference ingredient.
- Water exists by default at 70%, is editable, and is not removable in V1; recipes without water use 0%.
- Additional ingredients are freely named and default to percentage mode.
- Ingredient units are `percent` or absolute `grams`; absolute grams do not scale.
- Calculation modes are `totalMass` and `flour`.
- Intermediate calculations are never rounded; display uses at most one decimal place.
- Percentages may exceed 100%; percentage and gram values may not be negative.
- A preset stores only a formula, never the current batch size.
- Loading a preset preserves the current mode and target input.
- Persistence uses `panacalc.presets.v1` and `panacalc.session.v1`; persistence failure must not disable calculation.
- No backend, authentication, database, cloud sync, units other than grams, nutrition, costs, timers, dough-ball calculator, categories, folders, favorites, or social features.
- The PWA must work under GitHub Pages base path `/PanaCalc/`, be installable, and be usable offline after first load.
- Production deploys from `main` through GitHub Actions to GitHub Pages.
- Use Node.js 24 for local/CI reproducibility.
- Completion requires green `npm run lint`, `npm test`, and `npm run build`.

## Review Focus

- Decimal input using either comma or dot must parse predictably instead of silently producing the wrong quantity; pinned by `parseDecimalInput` tests in Task 2.
- In total-mass mode, fixed-gram ingredients equal to or greater than the target must yield a validation error and no misleading result; pinned by Task 2 validation tests.
- Corrupt or structurally invalid localStorage values must fall back safely without losing calculator functionality; pinned by Task 3 storage tests.
- A localStorage implementation that throws on read/write (privacy mode/quota/security error) must not crash rendering or calculation; pinned by Task 3 storage tests.
- GitHub Pages production output must resolve assets and PWA scope under `/PanaCalc/`, not root `/`; pinned by Task 7 config/build verification.
